## 3. TASK ZERO — AppIntro version/code mismatch (tree currently does not build)

Current state: `app/build.gradle` declares `com.github.AppIntro:AppIntro:5.1.0`, but
the intro code has been ported to the **6.x** API:

- `ui/intro/IntroActivity.java` — imports `com.github.appintro.*`, uses
  `AppIntroFragment.createInstance(...)`, `setSkipButtonEnabled(...)`,
  no `setProgressButtonEnabled(...)`.
- `ui/intro/SampleSlideFragment.java` — implements `com.github.appintro.SlidePolicy`
  and `SlideBackgroundColorHolder` (incl. new `getDefaultBackgroundColorRes()`).

These cannot ship together. Resolve one way or the other:

- **Option A (recommended, was the verified state):** set the dependency back to
  `com.github.AppIntro:AppIntro:6.3.1` and keep the ported code. 6.3.1 is current and
  resolves from JitPack; the port was verified against the published 6.3.1 sources
  (unpacked at `<outputs>/tools/appintro/` in the sandbox).
- **Option B:** keep 5.1.0 and revert the two intro files to the 5.x API
  (`com.github.paolorotolo.appintro.*`, `AppIntroFragment.newInstance(SliderPage)`,
  `showSkipButton`, `setProgressButtonEnabled`, `ISlidePolicy`,
  `ISlideBackgroundColorHolder`). Not recommended: 5.1.0 is 2019-era and the rest of
  the switch→if/else changes in `SampleSlideFragment` must be preserved either way.

API mapping used for the port (5.x → 6.3.1), for whoever builds the commit:

| 5.x | 6.3.1 |
|---|---|
| `com.github.paolorotolo.appintro.*` | `com.github.appintro.*` |
| `AppIntroFragment.newInstance(SliderPage)` | `AppIntroFragment.createInstance(SliderPage)` (`newInstance` exists but is not `@JvmStatic`, so not Java-callable) |
| `showSkipButton(b)` | `setSkipButtonEnabled(b)` |
| `setProgressButtonEnabled(true)` | removed; buttons enabled by default — delete the call |
| `setColorTransitionsEnabled(b)` | unchanged |
| `ISlidePolicy` | `SlidePolicy` (same two methods) |
| `ISlideBackgroundColorHolder` | `SlideBackgroundColorHolder`; must implement **both** deprecated `getDefaultBackgroundColor()` and new `getDefaultBackgroundColorRes()` plus `setBackgroundColor(int)` |
| `SliderPage(title, desc, drawableRes, colorInt)` | same positional constructor works (`@JvmOverloads`) |

## 4. Inventory of working-tree changes and the reason for each

Build system:

- `build.gradle` — AGP 3.5.2→8.13.2; jcenter→mavenCentral (jcenter is dead); JitPack
  kept (AppIntro); `task clean`→`tasks.register` + `layout.buildDirectory`.
- `app/build.gradle` — `namespace` added (required AGP 8); compileSdk/targetSdk 36;
  Java 17; `buildToolsVersion` dropped (AGP default); deps bumped to current stable
  (appcompat 1.7.1, material 1.14.0, navigation 2.9.6, constraintlayout 2.2.1,
  recyclerview 1.4.0, preference 1.2.1, coordinatorlayout 1.3.0, junit 4.13.2,
  test-ext 1.3.0, espresso 3.7.0); removed unused `legacy-support-v4`,
  `lifecycle-extensions`, duplicate material lines, `fileTree(libs)`.
- `gradle.properties` — jvmargs 1536m→2048m; `android.enableJetifier` removed (no
  pre-AndroidX deps remain once AppIntro ≥6).
- `gradle/wrapper/*`, `gradlew`, `gradlew.bat` — wrapper 5.4.1→8.14.3, regenerated.

Manifest (`app/src/main/AndroidManifest.xml`):

- `package` attribute removed (AGP 8 hard-errors; namespace lives in build.gradle).
- `android:exported` added to every component with an intent filter (install-blocker
  at targetSdk ≥31): `true` for MainActivity, MainActivityAlias,
  DueProcessDeviceAdminReceiver; `false` for IntroActivity, CodeConfigActivity.
- `POST_NOTIFICATIONS` permission added (Android 13+; notifications silently dropped
  without it).
- `<queries>` block for `android.app.action.PROVISION_MANAGED_PROFILE` added —
  Android 11+ package-visibility filtering otherwise makes
  `intent.resolveActivity(...)` in `SetupFragment.provisionManagedProfile()` return
  null and the setup flow dead-ends with the "provisioning is not enabled" toast.

Java:

- `ui/intro/IntroActivity.java`, `ui/intro/SampleSlideFragment.java` — AppIntro 6 port
  (§3) + switch→if/else on `R.layout.*`/`R.id.*`.
- `ui/management/AppListAdapter.java`, `ui/management/LockdownFragment.java`,
  `ui/setup/SetupFragment.java` — switch→if/else on resource IDs. Reason: AGP 8 makes
  app-module R fields non-final; `case R.id.x:` no longer compiles. (Do NOT instead set
  `android.nonFinalResIds=false`; it is deprecated and scheduled for removal.)
- `util/NotificationUtil.java` — `PendingIntent.getActivity(..., 0)` →
  `PendingIntent.FLAG_IMMUTABLE`. Mandatory: targetSdk ≥31 throws
  `IllegalArgumentException` at runtime without an explicit mutability flag.
- `util/PostProvisioningTask.java` — wired up the existing-but-never-called
  `autoGrantRequestedPermissionsToSelf()` inside
  `performPostProvisioningOperations()`, so the profile-owner self-grants
  POST_NOTIFICATIONS with zero UI. (Profile owners may not self-grant
  camera/mic/location this way, but notifications are fine.)
- `res/layout/fragment_app_management.xml` — removed `android:gravity="center"` /
  `android:textAlignment="viewStart"` conflicts on 4 TextViews (lint `RtlCompat`
  errors; rendered behavior unchanged — start-aligned text).

## 5. Atomic commit plan

Construct commits in this order with `git add <files>` per step (changes are cleanly
per-file separable; no `add -p` needed except none). Caveat, stated honestly: commits
1–5 cannot be *build-verified* in isolation because the old toolchain (AGP 3.5) cannot
run on any JDK available here; they are nonetheless semantically independent and
compile-compatible with both old and new toolchains, **except** the `<queries>` element
in commit 3, which old AGP cannot parse — hence build-system lands before manifest. Use
this order:

1. `refactor: replace switch on resource IDs with if/else`
   — `AppListAdapter.java`, `LockdownFragment.java`, `SetupFragment.java`, and the two
   switch conversions inside `SampleSlideFragment.java` *if doing surgical staging*;
   simpler: include `SampleSlideFragment.java` switch hunks here only if comfortable
   with `git add -p`, otherwise fold them into commit 6.
2. `fix: add FLAG_IMMUTABLE to notification PendingIntent`
   — `NotificationUtil.java`.
3. `fix: resolve RtlCompat lint errors in app management layout`
   — `fragment_app_management.xml`.
4. `feat: self-grant runtime permissions after provisioning`
   — `PostProvisioningTask.java`.
5. `build: upgrade to AGP 8.13.2 / Gradle 8.14.3 / SDK 36 / Java 17`
   — `build.gradle`, `app/build.gradle` (with AppIntro still at **5.1.0** in this
   commit so the dep bump stays paired with its code port), `gradle.properties`,
   `gradle/wrapper/gradle-wrapper.properties`, `gradle/wrapper/gradle-wrapper.jar`,
   `gradlew`, `gradlew.bat`.
6. `feat: modernize manifest for Android 12+ (exported, notifications, queries)`
   — `AndroidManifest.xml` (package-attr removal must ride with or after commit 5;
   keeping all manifest changes here, immediately after 5, is fine).
7. `refactor: migrate AppIntro 5.1.0 -> 6.3.1`
   — `app/build.gradle` (dependency line → `6.3.1`), `IntroActivity.java`,
   `SampleSlideFragment.java`.

Verify `assembleDebug` passes after commits 6 and 7 at minimum (§7). If staging
order proves awkward, an acceptable fallback is fewer commits — but never one.

## 6. Sandbox environment (Cowork) — read or you will waste hours

Constraints discovered the hard way:

- Each bash call runs in a **fresh container, hard 45 s limit**. `/tmp`, `$HOME`,
  installed apt/npm/go packages, and background processes **do not survive** between
  calls. Only these mounts persist:
  - project: `/sessions/<session>/mnt/dueprocess`
  - scratch: `/sessions/<session>/mnt/outputs` (= `<outputs>` below)
- Long downloads: use `curl -C -` (resumable) into `<outputs>`; long Gradle builds:
  just re-run the same command — incremental state + configuration cache persist via
  `GRADLE_USER_HOME` on the mount. Typically 1–3 re-runs to completion.
- The system Java is a **JRE without javac**. A full JDK 21 (Temurin) is unpacked at
  `<outputs>/tools/jdk21`.
- Android SDK lives at `<outputs>/android-sdk`. No sdkmanager was used: license files
  were written directly to `android-sdk/licenses/` and AGP auto-installed
  platform 36 + build-tools 36.
- Standalone Gradle at `<outputs>/tools/gradle-8.14.3` (the project wrapper works too,
  but would re-download the distribution once).

Note: `<outputs>` contents may not survive into a *new* chat session. If gone, rebuild
the toolchain: download Gradle 8.14.3 bin zip, Temurin 21 JDK (api.adoptium.net), and
recreate `android-sdk/licenses/android-sdk-license` containing the line
`24333f8a63b6825ea9c5514f83c2829b004d1fee`.

## 7. Canonical build commands (sandbox)

```bash
O=/sessions/<session>/mnt/outputs
export GRADLE_USER_HOME=$O/gradle-home ANDROID_HOME=$O/android-sdk JAVA_HOME=$O/tools/jdk21
cd /sessions/<session>/mnt/dueprocess
sed -i "s|^sdk.dir=.*|sdk.dir=$O/android-sdk|" local.properties      # sandbox value
timeout 40 $O/tools/gradle-8.14.3/bin/gradle assembleDebug assembleRelease lintDebug \
    --console=plain --configuration-cache 2>&1 | tail -5
# ... repeat until BUILD SUCCESSFUL/FAILED ...
cp $O/local.properties.user-backup local.properties                  # ALWAYS restore
```

Lint report: `app/build/reports/lint-results-debug.txt`.
APKs: `app/build/outputs/apk/{debug,release}/`.
On the user's machine: plain `./gradlew assembleDebug` with their SDK + JDK 17+.
